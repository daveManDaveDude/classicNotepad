# Windows Acceptance Coverage Ledger

This is an evidence map for the 17 rows in [Section 6 of the historical Windows reliability review](WINDOWS_RELIABILITY_REVIEW_AND_PLAN.md#6-acceptance-matrix). It records what the retained evidence demonstrates and where it does not meet the full matrix. It does not run or certify the full qualification matrix, define a supported-Windows set, or close a platform gate. The current high-level dispositions are in [Windows reliability status](WINDOWS_RELIABILITY_STATUS.md).

The [E13 current-host qualification baseline](WINDOWS_QUALIFICATION_BASELINE.md) records a fresh Release configure/build and 11/11 CTest pass. Its historical E10 Full reuse check remains pending because the fresh executable hash differs; it does not change any matrix row to qualified.

## Performance-measurements disposition

**Partial, limited to C4.** The C4 identity above ran three fresh processes per case and retained direct-dispatch/width-settlement/export/hash/Undo timings plus 10 ms sampled private-byte and working-set baselines/peaks for the 69 paste cases. Its report gives per-case medians and observed peaks. This is descriptive evidence for that Windows 11 build and viewport configuration, not a declared reference-hardware release baseline. The CPU/RAM reference machine, matrix-wide target/tail-latency distribution, editor-source bytes requested, and process handle counts were not recorded.

The remaining Section 6 performance distinctions are still open:

- Actual visible paint completion is not measured separately from a non-null model, published first-index counter, or a visible-window query.
- Background complete-index time is not compared with foreground stalls caused by viewport/status queries.
- Worker time is not separated from foreground snapshot allocation/clone time for a measured workflow.
- Allocated/retained inserted storage is not measured alongside the Undo-budget charge as process memory. `TextConversionTests::TestLargeDocumentUndoBudgetAndSharedOwnership` is model-level history/owner accounting only.

Three C4 repetitions provide sample medians for the tested cases, but they do not establish repeated median and tail-latency targets on declared reference hardware. This disposition does not close the broader performance or Windows qualification gates.

## Overall qualification status

The evidence above is a claim-to-evidence inventory, not a pass of the acceptance matrix. In particular, the real OS clipboard smoke, supported-Windows matrix, visible-app qualification, broader DPI/accessibility checks, physical printers, other printer drivers/configurations, and application-level resource-lifetime matrix remain **OPEN**. No supported Windows version set is inferred from the single retained Windows 11 build.
